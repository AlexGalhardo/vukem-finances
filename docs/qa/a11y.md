# Accessibility audit

Epic 24, task 12. The target is WCAG 2.2 level AA. The automated part runs on every page in two themes and three
languages; the manual part is a checklist for real devices.

## Automated checks

Run them with `bunx playwright test e2e/a11y`. The server and the database are the throwaway ones of
`playwright.config.ts` (set `E2E_PORT`, `E2E_SAAS_PORT`, `E2E_FAKE_PORT` and `E2E_TELEGRAM_PORT` to free ports).

| Spec | What it proves |
| --- | --- |
| `e2e/a11y/pages.spec.ts` | `@axe-core/playwright` (rule tags `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`, `wcag22aa` and `best-practice`) finds nothing on the 20 signed-in pages of the personal edition, in light and dark, in English, Portuguese (Brazil) and Spanish: 120 page loads |
| `e2e/a11y/public-pages.spec.ts` | the same for `/login` and `/forgot-password` before signing in |
| `e2e/a11y/saas-pages.spec.ts` | the same for `/billing`, `/admin`, `/admin/revenue`, `/workspace` and `/dashboard` on the saas server, and `/register` and `/login` signed out |
| `e2e/a11y/keyboard.spec.ts` | Tab walks of ten journey pages: no trap, a visible focus indicator and an accessible name on every stop; the transaction dialog and the shortcut help dialog trap focus and give it back; the theme buttons work with Enter and Space |

Pages not audited by axe:

- `/connected-apps` answers 404 unless the remote MCP server is configured, so the audit server has nothing to load.
- `/setup`, `/invites/{token}` and `/invites/{token}/register`, `/email/verify`, `/reset-password/{token}`,
  `/two-factor-challenge` need a one-time token or state; the structural checks of epic 06 cover them (labels, headings,
  landmarks).

The shortcut layer rules (never in a field, reserved combinations, the single-key switch) are proved by
`e2e/shortcuts.spec.ts`, `e2e/palette.spec.ts` and `e2e/shell.spec.ts`, which run in the same Playwright suite.

## Findings

Five accessibility bugs were found by the first run and fixed (QA-600 to QA-604 in [rounds.md](rounds.md)). The audit
now reports no violation on any page.
